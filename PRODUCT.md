# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers on a team, daily: people who write queries against this database and need a column, a relation
or a diagram fast, beside their editor. Confirmed by the owner on 1 November 2026. New joiners and coding
agents meet the same page when learning the database, but the regular is who it is tuned for.

## Product Purpose

dbtour reads a database, writes what it finds to one model file in the repository, and renders that file as
Markdown GitHub shows and as one HTML page developers search, follow relations in and hand to an agent. The
page is this surface. Success: the answer to "what is in this table and what does it touch" in seconds,
without a database connection and without leaving the page.

## Positioning

Everything is a function of one committed model file, and a notes file people write wins over what the
database says. So a production SQL Server nobody may alter still gets descriptions, undeclared relations and
groups, and the page shows them beside the real keys. The page is one self-contained HTML file with no
network, so it opens from disk and deploys anywhere.

## Operating Context

Two scenes, both confirmed: open all day beside an IDE on a second monitor or split screen, often in dark
mode; and a deployed docs site opened from a link when a question comes up. The page is generated by
`dbtour render` from `schema.json` plus `dbtour.notes.yaml`; it is read-only and has no modes. Diagrams are
on demand, a table with its neighbours, never the whole schema.

## Capabilities and Constraints

- Search over tables, columns and groups; a table view with columns, keys, relations both ways, indexes,
  constraints and a view's definition; a neighbourhood diagram that expands one node at a time; groups as
  diagrams; "Copy for Claude".
- Must work offline from a `file:` URL: no webfonts, no network assets, no external images. Fonts are system
  stacks; every graphic is inline SVG or CSS.
- Built with React, React Flow and ELK into one bundle; dark mode follows the system.
- Terminology: table, view, column, relation, group, notes, model. Refs are `schema.table`.
- The page holds structure, never rows.

## Brand Commitments

Name: dbtour, lower case. Spelling in docs is British. Logo: none yet; the owner wants a full identity for
this round, a mark, a wordmark, an inline favicon and a social image, usable in the page, the README and on
npm. Confirmed on 1 November 2026: nothing playful or marketing-like; the brand never louder than the
content, the database name and its tables lead; and it must not look like every other docs tool.

## Evidence on Hand

- `examples/shop`: a sample model (a small web shop) and notes, rendered by `npm run example`.
- `PLAN.md`: the design the owner agreed, including the page's intended behaviour.
- No customers, benchmarks, testimonials or usage numbers exist; none may be invented.

## Product Principles

- The content is the interface: columns, keys and relations are the page, chrome stays out of their way.
- Scanning speed beats expression; identity lives in precise details.
- The notes win: what people wrote shows beside what the database says, and is marked as such.
- Works from a file, forever: no dependency on a server, a font host or a CDN.
- The agent is a reader too: anything shown can be handed over as plain Markdown.
